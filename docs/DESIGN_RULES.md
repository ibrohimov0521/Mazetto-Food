# MAZETTO FOOD Design Rules

AliPOS screenshots and workflows are functional references only. They are not visual references.

Do not copy AliPOS:

- purple colors
- layouts
- navigation style
- tables
- buttons
- visual hierarchy
- spacing
- legacy desktop UI patterns

MAZETTO FOOD must have its own completely modern design.

## Visual Identity

The future MAZETTO visual identity is based primarily on:

- white
- green
- blue

The interface should feel:

- modern
- clean
- premium
- fast
- professional
- easy to understand
- optimized for touchscreens
- responsive

Avoid overly colorful dashboards.

## Semantic Color Use

Green should represent:

- success
- completed states
- primary positive actions
- online/active states

Blue should represent:

- navigation
- informational actions
- selected states
- secondary primary actions

White and very light neutrals should be used for:

- primary surfaces
- backgrounds

Neutral dark text should provide strong readability.

Red should only be used for:

- destructive actions
- cancelled states
- serious errors

Orange/yellow may only be used sparingly for:

- warning
- pending
- attention states

Exact hexadecimal colors must not be chosen yet. That belongs to the dedicated Design System stage.

## Avoid

Future screens should not look like legacy Windows software.

Avoid:

- excessive borders
- tiny buttons
- tiny text
- dozens of browser-like tabs
- dense uncontrolled tables
- unnecessary colors
- visual clutter

## Desktop

Desktop interfaces should use appropriate side navigation or top navigation depending on context.

Desktop layouts may use tables where appropriate, but tables must be controlled, readable, responsive, and task-focused.

## Mobile And Tablet

Mobile interfaces should use:

- drawers
- bottom navigation
- bottom sheets
- responsive card/list representations where appropriate

Tables on desktop must transform appropriately on small screens rather than causing page overflow.

Critical functionality must never be desktop-only.

## Responsive Validation Widths

Future UI must be validated at:

- 375
- 390
- 430
- 768
- 1024
- 1366
- 1440
- 1920

## Mandatory UI Quality Rules

Future interfaces must have:

- no horizontal page overflow
- no clipped cards
- no inaccessible action buttons
- no text escaping containers
- no critical desktop-only action

These rules apply to Customer Web, POS, Admin, Telegram web-linked flows, and future device-focused interfaces where applicable.
